# Security-Sensitive Domain Rules

Use when auth, privacy, billing, audit logs, secrets, or data migration are involved.

- Do not invent authorization, privacy, billing, or audit behavior.
- Require explicit acceptance criteria for who can see/change sensitive data.
- Do not paste secrets, tokens, database URLs, or private user data into docs, issues, logs, or reports.
- Prefer stricter spec review and evaluation checks for sensitive changes.
- Record open product/domain questions instead of guessing.
